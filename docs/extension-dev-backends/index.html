后端

原生与 Python 后端、进程环境与生命周期、协议概要、宿主接口及其权限、钩子、提供者回调和扩展之间的服务调用。

后端是扩展在开启期间运行的程序。它与应用通过自己的标准输入和标准输出通信，可以调用应用的宿主接口，并回答应用对它的调用：钩子、实例类型的提供者回调、面板与视图的调用，以及其他扩展的服务调用。

本页概述后端需要了解的内容。每个方法的参数、结果、权限和限制见接口参考，各方法的语义见扩展后端协议参考。用 SDK 编写后端见 SDK。

两种后端

每个操作系统一个可执行文件，路径相对于软件包根目录。没有当前系统的程序时，扩展显示“无法运行”。在 Linux 和 macOS 上，打包时保留程序的可执行权限。

进程与环境

  • 工作目录为扩展包根目录。安装副本位于 extensions/<id>/<version>/，开发链接则使用用户选中的源目录。按包根目录读取随包资源，通过 HANAFUBUKI_EXTENSION_DATA 或 storage.path 获取持久化文件的写入目录。

  • 环境变量：从干净的环境开始，只传入应用环境中以下存在且为文本的变量：PATH、HOME、USER、LOGNAME、SHELL、TMPDIR、LANG、LANGUAGE、LC_*、TZ、XDG_RUNTIME_DIR，以及 Windows 上的 USERPROFILE、SYSTEMROOT、SYSTEMDRIVE、WINDIR、COMSPEC、PATHEXT、TEMP、TMP、APPDATA、LOCALAPPDATA、PROGRAMDATA、PROGRAMFILES、NUMBER_OF_PROCESSORS、PROCESSOR_ARCHITECTURE。另外设置：

    • HANAFUBUKI_EXTENSION_ID：扩展 ID；
    • HANAFUBUKI_EXTENSION_DATA：扩展的数据目录 extensions/<id>/data/，更新时保留。

    应用的令牌、密钥和代理设置都不会传给后端。

  • 输出：标准输出只用于协议，不能写入其他内容。标准错误写入扩展的日志 backend.log（超过 1 MiB 时轮转），log.write 也写入这里。用户在扩展卡片上点击“查看日志”可以看到最后 256 KiB。

后端不是沙箱

后端以用户的权限运行。清单中的权限只限制它能调用哪些宿主接口，原生程序仍可以直接访问网络和文件系统。不要依赖权限来约束自己的代码，也不要让用户以为它们能做到这一点。

生命周期

阶段发生什么
启动扩展开启时启动进程，发送 initialize（10 秒内回答）；更新后若声明了 migrate 则调用它；声明了 activate 则调用它。三者合计须在 16 秒内完成，否则启动失败
运行每 10 秒发送一次 ping，须在 5 秒内回答
停止声明了 deactivate 则调用它，然后发送 shutdown，各最多 1 秒；随后关闭标准输入，再给进程 1 秒退出，之后强制结束。它通过 process.run 启动的进程也一并停止

在 initialize 中回答的协议版本必须为 1，否则启动失败。

故障

以下情况视为后端故障：进程退出、输出关闭、发送不是协议帧或不是 JSON-RPC 消息的内容、帧大于 4 MiB、标准输入不再接收、错过一次 ping，或连续三次调用超时（普通调用 30 秒，钩子 10 秒）。

发生故障时，等待中的调用全部失败，扩展进入“失败”，并按重启策略在 2、10、30 秒后自动重启（10 分钟内最多 3 次）。应用正常退出期间后端结束不算故障。

反复崩溃：每次启动前计数加一；后端稳定运行 30 秒、被正常停止或用户点击“重试”后清零。计数达到 3 时，扩展显示“因反复崩溃已停止”，在本次运行和之后的运行中都不再启动，直到用户点击“重试”。

协议概要

  • 传输：JSON-RPC 2.0，应用写入后端的标准输入，后端写入标准输出。
  • 分帧：与 Language Server Protocol 相同：若干 Name: value 头部行（以 \r\n 结尾），一个空行，然后是恰好 Content-Length 字节的 UTF-8 JSON。Content-Length 必填，名称不区分大小写，其他头部被忽略。头部最多 1 KiB，消息体最多 4 MiB。
  • 版本：协议版本 1，由 initialize 双向确认。
  • 双向调用：双方都可以随时调用对方。后端处理某个调用时可以调用宿主接口并等待结果。参数中未知的成员会被忽略，缺失的成员取默认值；参数无法读取时调用以 INVALID_PARAMS 失败。
  • 并发：应用同时最多回答同一后端的 16 个调用，超出的以 BUSY 失败。
  • 时限：应用对后端的调用（钩子除外）时限为 30 秒，单次超时只影响该调用，连续三次超时视为故障。

钩子

钩子只在 initialize 的回答中通过 hooks 列出时才会被调用，未知的名称被忽略。

钩子何时调用时限
activate每次启动，initialize（及 migrate）之后10 秒
migrate更新后的第一次启动，参数 fromVersion 为被替换的版本10 秒
deactivate停止时，shutdown 之前1 秒
uninstall卸载前（后端正在运行时）；失败只记录日志，不阻止卸载10 秒
ui不是一次调用：表示后端有界面状态（ui.state、ui.call、ui.emit，见界面）每次调用 10 秒
diagnostics用户收集诊断时，通过 diagnostics.collect 提供文档30 秒

不声明 migrate 的后端更新时不会收到迁移调用：声明它就是表示数据需要迁移。被替换的版本只在内存中保留到新版本第一次启动，若在此之前应用重启，迁移调用会丢失。

宿主接口

后端可以调用的方法。需要权限的方法会根据安装时授予的权限检查，被拒绝时返回 PERMISSION_DENIED。这些方法是独立的一组接口，不能访问应用自身的命令。访问应用自身功能的唯一途径是管理目录（tools.list、tools.call）：与内置 Agent 和 MCP 客户端相同的工具，受 management 权限限制，每次修改都需等待用户确认。

要点：

  • host.info 返回应用版本、协议版本、语言、平台（linux、macos、windows）、instancesDir（新实例默认所在的文件夹）和 mirrors（用户当前在设置中选择的下载镜像）：automatic（用户将镜像交给 sd_webui_all_in_one 自动检测，即其 auto_mirror，下面的开关作为它的输入）以及 pypi、github、huggingface，每项为 { enabled, custom }（custom 为用户自己的镜像地址或 null；PyPI 没有自定义镜像）。通过 download.fetch 的显式 source 使用宿主镜像策略；direct 保留原始 URL。自行联网的脚本仍需自行应用策略。settings.get 返回扩展的设置值；settings.patch {patch} 只修改自身已声明字段并返回 canonical {values}；storage.path 返回数据目录。
  • log.write 可以作为调用或通知发送，级别为 error、warn、info（默认）或 debug。
  • instances.list、instances.get 返回只读的实例信息：id、name、type、path、running 和 components（按组件名，每个为 { path, external }：平台原生形式的文件夹，以及它是否为用户自己的文件夹；实例的组件无法解析时为空）。框架或面板的调用只带实例 id，请在其中通过 instances.get 读取组件：它们会跟随用户在“路径”中的修改。servers.status 返回每个服务器角色的 instanceId、role、status（stopped、starting、running、restarting、stopping、failed）和 endpoint。
  • process.run 接收 argv（不经过 shell）、cwd 和追加到干净环境中的 env，立即返回 taskId；输出通过 process.output 通知发送，结束时发送 process.exit。process.cancel 停止它。这些进程随后端一起停止。useHostProxy: true 显式给这个子进程注入当前宿主代理环境，并覆盖 env 中的同名值；默认为 false。主动选择后，该子进程可读取这些代理值及其中可能含有的凭据。 任务详情保留标准输出和错误输出，可查看、复制或导出。指定自有类型的 instanceId 可以从其管理窗口找到这条进程任务。
  • download.fetch 接收 url、可选的 sha256 和 destination，返回 {path, sha256}。可选 source 为 direct（默认）、github 或 huggingface；显式来源必须匹配 URL，并应用当前宿主镜像策略。cache: true 仅在提供 sha256 时复用经过摘要校验的内容；无摘要时正常下载。命中后复制到扩展的目标文件，不暴露缓存路径或写权限。下载失败不替换原目标文件。 任务中心记录传输的字节数，响应缺少总长度时使用不定进度条。
  • http.request 通过宿主代理执行有界 UTF-8 HTTP。参数为 url、method（默认 GET，另支持 HEAD、POST、PUT、PATCH、DELETE、OPTIONS）、可重复的 {name, value} headers 列表、可选文本 body、maxBytes 和 timeoutMs。限额只能缩小生成参考中展示的宿主默认值。返回 {status, headers, body}；HTTP 404/500 也正常返回状态。无效输入为 INVALID_PARAMS，未授权主机为 PERMISSION_DENIED，网络、大小或 UTF-8 失败为 REQUEST_FAILED。二进制文件使用 download.fetch；请求不会自动注入宿主凭据。
  • python.ensure 在指定位置安装应用支持的 Python 版本；git.clone（目标不能已存在）和 git.pull（只快进）使用应用的 Git，不会弹出凭据提示，并经过应用的代理。三者都立即返回 taskId（首次运行时若应用仍在准备 Git，git.* 会先等它就绪），作为任务出现在任务中心，以 process.exit 结束，可用 process.cancel 停止。
  • instances.scan 接收绝对路径 path，像“扫描”一样对这个文件夹运行应用的实例发现：识别应用已知的 WebUI 布局和所有已注册类型的发现签名并添加为实例，返回 attached（新实例的 id）和 warnings（除完整新实例外的所有结果，例如已经是实例的文件夹，或找到但缺少 Python 的 WebUI——它已被添加但仍需安装；请宽松地读取）。instances.import 接收 type、绝对路径 path，以及可选的 name、componentPaths（绝对路径或相对于 path）和 values，把该文件夹导入为该类型的就绪实例并返回 id；该文件夹和每个组件文件夹都必须存在，已被实例使用的文件夹会被拒绝。两者都在完成后才返回，不是任务中心中的活动：扫描大文件夹可能需要一段时间，所以请先回答视图或面板的调用，在自己的线程中扫描，并用 ui.progress 报告进度。停止后端会取消扫描。
  • ui.notify（info、warning、error）和 ui.progress（相同 id 更新同一项）显示为任务中心中的活动。ui.progress 可传入本扩展类型的 instanceId，在该实例管理页显示进度，此时 id 的范围是该实例。 在上报进度时指定 showOnHome: true，运行中的任务也会显示在首页状态区。
  • tools.list 列出管理工具及每个工具所需的 management 级别；tools.call 接受工具的 name 和 arguments，回答工具本身的结果（全部工具见接口参考）。修改会在应用窗口中以扩展的名义询问用户（最长一分钟），并记录到任务中心，因此请在自己的线程中调用，不要在应用等待的视图或面板调用中调用。它不能重启扩展自己的行或其依赖的扩展。按工具的 builtInOnly 标记判断适用范围。扩展实例类型采用内置管理能力并声明相应分区后，也能使用版本、扩展、模型和环境分区的工具。install_extension 给 WebUI 实例安装插件，list_host_extensions 列出 Hanafubuki 已安装的桌面扩展。
  • events.subscribe 会整体替换订阅。每次传入全部需要的主题，传 {"topics":[]} 可取消订阅。宿主每 2 秒检查一次实例和服务器状态的变化。从设置页、视图或后端成功写入扩展设置后，settings 事件在 event.params.data.values 中带回保存后的有效值。task 主题为此扩展通过 tools.call 启动的任务中心活动发送 {phase, activity}，阶段为 start、progress、end。
  • 如果扩展要使用可选接口，先在 host.info 的 capabilities.methods 或 capabilities.topics 中查找名称。扩展实际获授的权限可从 initialize.permissions 读取。

发给后端的通知：event（topic 和 data）、process.output（taskId、stream、data）和 process.exit（taskId、status 为 exited、failed 或 cancelled、exitCode、error）。

提供者回调

声明 provider = "backend" 的类型通过回调校验参数、生成安装和启动计划。带后端的声明式类型也可提供按实例加载的启动选项，也可单独接入更新检查或自定义维护操作，继续使用静态安装和启动计划。每个回调的时限为 30 秒。详见实例类型。

回调中的 instance 包含 id 和按名称索引的 components。例如 instance.components.core.path 是 core 当前的本机路径，external: true 表示这是用户拥有的目录。检查组件时读取该路径，返回计划时使用 {component.core}。已有实例使用新参数重装时，provider.validateSpec 会收到这个对象；创建时还没有实例。

只有声明了 update-check 的类型才会被调用 provider.checkUpdate：卡片上的“检查更新”和每日更新检查都会调用它，每日检查对每个实例依次调用一次。它是只读的：实例可能正在运行，检查不能改变任何内容。请尽快回答：在实例之间缓存或共享获取到的内容（例如发布列表），因为超过 30 秒的调用会失败，连续三次超时会结束通道。返回的错误会显示为该实例这次检查的错误。

自定义操作在实例停止时运行，期间实例处于独占维护状态；实例正在运行或另有维护进行时会被拒绝。除了实例的管理页面，MCP 客户端和内置助手也可以通过管理 MCP 服务器的 run_instance_operation 工具运行它，外部客户端需要“完全访问”权限才能免确认调用（管理 MCP 服务器）。

通过 instances.configuration 传入 { id }，可以读取自己类型的单个实例。values 和 launchValues 分别返回已声明的非秘密安装字段和启动字段，包括默认值。凭据会被遮盖。valuesTruncated 和 launchValuesTruncated 标明结果是否被截断。

面板和视图的调用（ui.panel.query、ui.panel.action、ui.frame.call）、界面状态的 ui.state 和 ui.call，以及 ui.frame.emit 和 ui.emit 通知见界面。这两个只能作为通知发送：作为请求发送时，应用回答 METHOD_NOT_FOUND。

  • 目标出错或在调用中途结束，只使该调用失败；目标的故障只影响目标自己。

宿主偏好只读快照

需要查询模型下载来源或 Micromamba 镜像开关时，具有管理读取权限的后端可通过 tools.call 调用 get_app_runtime_status，传入 {"runtime":"mirrors"}，读取 modelSource 和 useMicromamba。

host.preferences {} 无需额外权限，返回 {locale, instancesDir, mirrors, network}。语言、native 实例目录与镜像沿用 host.info 的含义及 null 默认值；network 仅包含 proxyMode（system、manual、disabled）和 proxyConfigured。已配置不代表代理有效或可达。快照不含代理 URL 或凭据，也不能修改应用设置。

用 events.subscribe 订阅 preferences，再通过 host.preferences 读取当前快照。每条对应的 event 在 params.data 中携带同型完整快照。相关宿主设置成功保存后发布；代理地址改变时即使公开字段不变也会发布。无关设置或保存失败不发布。后端重启后重新订阅并读取，没有事件重放。settings 仍只表示扩展自己的设置。

生成的事件主题参考 从协议 registry 直接展示 payload 字段及权限。

运行时工具与诊断文档

runtime.status {tool?} 读取现有 readiness 快照，不启动准备。不传 tool 时列出 python、git 和 micromamba。每项包含 tool、status（notReady、preparing、ready、failed、unavailable），以及可选的 native path、已验证的版本或版本命令输出 version、error。读取无需额外权限，version 不保证是语义化版本字符串。

runtime.resolve {tool} 要求 processes = true。它等待宿主已有的准备流程，返回 {tool, path, version}；模块不可用或准备失败时返回实际原因。后端停止会取消等待。SDK 不用较短的客户端计时器截断准备。将返回的 native 可执行文件路径传给 process.run 即可使用工具；不开放删除工具或修改运行时配置的接口。

要提供单个实例的诊断文档，声明 diagnostics.collectInstance。宿主传入该扩展所属类型的实例 {id}，将文档写入实例诊断目录下的 extensions/<id>/。Rust 实现 InstanceDiagnostics 并从 Handler::instance_diagnostics 返回，Python 覆盖 diagnostics_collect_instance(host, instance_id)。

后端在 initialize.hooks 声明 diagnostics，以 {documents: [{name, text}]} 回答 diagnostics.collect {}。name 是单个文件名，不是路径；text 可为普通文本或序列化 JSON。宿主写入诊断 workspace 的 app/extensions/<id>/，内容不得包含凭据。扩展停用或卸载后移除贡献；采集失败或超时记为 bundle issue，其他贡献继续。生成的方法参考直接展示实际调用时限、最大文档数和总字节限制。

上面的 Python 清单直接来自完整 configuration-python 包，实际 backend.py 使用 SDK 的 initialize/ping/shutdown 协议循环。包验证只检查文件，不准备托管 Python 或启动后端；单独的本地协议 smoke 不代表桌面验收。原生命令映射片段说明如何选择可执行文件，不是可直接安装的完整包；该路径应构建并打包 greeter 示例。

后台询问用户

后台操作需要用户选择时，调用 ui.prompt，例如 Python 的 host.ui_prompt({"id": "model-name", "kind": "text", "message": "模型名称？"})。 每个问题使用新的本地 ID。方法在问题受理后返回，主窗口以扩展 ID 标明来源。 在后端的通知回调中处理 ui.prompt.result，按 id 关联操作： accepted 表示确认，text 是提交的文本，允许为空字符串；取消和确认类问题的 text 是 null。每个后端可保留一个待答问题，再次询问会得到 BUSY。 后端停用或重启时撤回待答问题。管理操作仍使用宿主自己的确认。
