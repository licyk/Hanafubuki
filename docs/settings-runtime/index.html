运行环境

检查并配置应用 Python、Micromamba 和 Git。

运行环境页显示 Hanafubuki 自己依赖的 Python、Micromamba 和 Git。它们属于应用级运行时，与每个 WebUI 实例自己的 Python 和 Core 相互独立。

阅读状态面板

每个面板会显示当前状态、准备步骤、错误和已检测信息：

面板重点信息
应用运行环境Python 版本、可执行文件、Python 目录、Launcher Code 和应用 API
Micromamba内置版本、检测版本、可执行文件和 SHA-256
Git检测版本、可执行文件、安装任务和 Conda 根修复状态

状态为“准备中”时查看当前步骤，不要连续点击重试。状态为“失败”时先展开错误，记录失败阶段和详细信息；面板允许重试时再使用重试按钮。

选择应用 Python

“应用 Python 版本”支持当前界面列出的 Python 版本。修改会立即保存，但只在下次启动时切换应用运行时。

完成正在运行的安装、管理和 Agent 任务。
选择需要的应用 Python 版本，等待保存完成。
正常退出并重新启动 Hanafubuki。
返回运行环境页，确认版本、可执行文件和应用 API 均为就绪状态。

切换应用 Python 不会重装实例 Python，也不会改变实例选用的 Python 版本。实例环境问题应在对应实例的管理页处理。

选择 Git 来源

来源行为
优先使用系统 Git下次启动时检查系统 PATH 中的 Git；不可用时自动回退到 Micromamba Git
使用 Micromamba Git跳过系统 Git，始终使用应用托管的 Git

Git 来源同样在下次应用启动时生效。系统已经安装可用 Git 时通常保留默认选择；需要固定、隔离的 Git 环境时再选择 Micromamba。

失败排查

  • Python 下载或校验失败：检查网络、代理、镜像、磁盘空间和受管运行时目录权限。
  • Micromamba 失败：确认没有第二个应用进程占用运行时，并检查目标磁盘是否可写。
  • Git 等待 Micromamba：先让 Micromamba 完成准备，这不是独立的 Git 卡死。
  • 状态订阅不可用：使用面板重试；仍失败时生成应用诊断包。

不要直接替换受管文件

不要从外部覆盖受管 Python、Micromamba、Conda 或 Launcher Code。应用会按自己的版本和校验规则准备这些组件，手动修改可能在下次检查时被判定为损坏。
