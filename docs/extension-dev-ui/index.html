界面

扩展的设置表单、面板（info、table、log、actions、progress、status、list、markdown、empty、loading）、推送给面板和视图的界面状态、视图（frame）的加载方式、客户端接口、主题变量与安全限制，以及文字与多语言。

扩展可以通过四种方式出现在应用界面中。设置表单和面板由应用用自己的组件渲染，扩展只提供描述和数据；视图（frame）是扩展自己的 HTML 页面，在沙箱 iframe 中运行；文字供上述所有内容和实例类型描述引用。视图协议、界面套件的每个类、面板块和表单字段的完整列表见接口参考。

方式由谁渲染数据来源需要后端
设置应用扩展的设置存储否
面板应用ui.panel.query、ui.panel.action，或界面状态是
视图扩展页面ui.frame.call、ui.frame.emit、界面状态调用时需要
文字应用locales 文件否

在管理面板或 frame 的 contributes.ui 项中可设置 types = ["notes"]，只为指定的扩展内实例类型显示该页面。省略时该扩展的全部类型都可见。

文本的写法

设置表单和面板是 JSON 文件，其中每处文本使用以下两种形式之一：

literal 依次选用当前语言、英语、表中第一项。key 引用扩展自己的文字，须以 ext.<扩展 ID>. 开头，还可以用 params 填入译文中的占位符。例如，"params": { "name": "Greeter" } 会替换译文中的 {name}。文字与多语言

设置

清单的 contributes.settings 指向一个 JSON 数组，每项是一个表单字段。扩展开启后，设置窗口中会出现以扩展名称命名的分区。

键说明
key必填，由 A-Z、a-z、0-9、_、- 组成，不能重复
kind必填：text、number、boolean、select、multiselect、path、secret、slider、textarea
label必填，文本
help帮助文本
optionsselect 和 multiselect 必填：{ "value": "…", "label": 文本 } 的列表
min、max、step数字范围与步长；slider 必须同时有 min 和 max
pathKindpath 字段：directory 或 file
nullable、unsetLabel允许“未设置”作为一个可选值，unsetLabel 为它的文本
required、default是否必填；默认值
visibleWhen、requiredWhen、disabledWhen、disabledReason条件，写法与实例类型的参数相同
advanced有可用默认值的次要字段
commitchange、blur 或 manual；manual 的字段需要点击保存才提交
patchGroup同组字段一起提交

optionsSource 不能使用，它只用于应用自己的表单。

设置值保存在扩展自己的存储中（extensions/<id>/settings.json），不属于应用设置。只有扩展处于运行状态时设置分区才能读取和保存；应用会用整个表单检查修改，任何字段不通过都不会写入。后端用 settings.get 读取这些值；订阅 settings 事件后，用户每次保存都会收到通知。字段被删除或不再接受某个已保存的值时，该值会被忽略，分区显示默认值。

使用 [[contributes.settingsGroups]] 按显示顺序列出本扩展的字段键。每组提供本地化标题，可选填内置设置分类，如 automation 或 runtime。可用分类为 language、paths、network、mirrors、runtime、environmentTools、logs、webview、automation 和 about；modules 和 extensions 使用固定布局的页面，不接受分组，填写其他值会在安装时指出位置。扩展自己的设置页也显示所有组及未分组字段。两个入口都保存到所属扩展的配置。后端或其他窗口保存后，已打开的表单会刷新，并保留用户尚未提交的编辑。

面板

在清单的 contributes.ui 中选择 slot = "home.sections"，可以在首页实例网格下方展示 schema 面板。选择 slot = "taskCenter.tabs"，面板会作为任务中心的标签显示，停用扩展时会回到任务列表。这两个位置收到的实例上下文均为空。独立页面可在 slot = "pages" 的 frame 清单项加 home = true，首页快捷卡和标题栏入口会打开同一页面。

管理或诊断面板以及 actions 中的独立按钮支持 "cardMenu": true。在匹配类型的实例卡片上打开菜单即可使用同一份表单、确认和维护操作。可同时声明 toolbar，把同一动作放在两个位置。

把 schema 面板声明到 slot = "management.overview"，即可在实例概览中显示只读的 info、status、table 和 progress。可用 types 限定实例类型，数据支持查询和状态推送。在 management.sections 的 actions 块内，按钮可声明 {"id":"repair","operation":"repair-index","label":{"kind":"literal","text":{"zh":"重建索引"}}}，它使用当前类型的 management.forms.repair-index 表单和确认文案，在独占维护期间执行。当前类型没有该操作时，按钮会隐藏。重新加载开发链接会刷新同版本扩展的面板和翻译。

把检查面板的 slot 设置为 management.diagnostics，就能在实例诊断页显示检查结果。可用状态或列表展示结果，行上的修复按钮引用已有维护操作。需要随诊断包导出的文件继续由 diagnostics.collectInstance 提供。

在管理或诊断 schema 面板上添加 "toolbar": "button"，就能从该实例的顶部栏直接打开它。也可以把这个属性写在 actions 块的独立按钮上，使用该动作的名称和确认。设置 "toolbar": "externalBrowser" 后，WebUI 显示时会用该快捷动作替换浏览器按钮。WebUI 标签管理器的右键菜单仍可打开当前页面。

在清单的 [contributes] 中选择面板的显示位置，用 source 指向包内的面板 JSON 文件。

面板有 id、title 和 blocks。同一扩展的面板和视图共用一组 ID，即使放在不同位置也要分别命名。每个块有 kind、在面板内唯一的 id（A-Z、a-z、0-9、_、-）和可选的 title。同一面板中所有 actions 块和 list 块也共用一组操作 ID。

kind额外的键后端为 ui.panel.query 返回
info无{ "rows": [{ "label": …, "value": … }] }
tablecolumns：至少一列，每列 key（唯一）和 label{ "rows": [{ "<列 key>": 值 }] }
logfollow：为 true 时随新行到达停在末尾，直到用户向上滚动{ "lines": ["…"] }
actionsactions：至少一个，每个有 id（唯一）、label，可选 confirm（执行前确认的文字）和 fields（表单，写法与设置相同）无数据
progress无{ "value": 0.42, "label": "…" }：value 从 0 到 1；不是数字时进度条显示为不确定
statusinline：为 true 时在消息旁显示徽标，而不是消息条{ "severity": "warning", "title": "…", "message": "…" }：info、success、warning 或 error
listactions：每行可提供的按钮，写法与 actions 块相同，但没有 fields{ "rows": [{ "id": "…", "title": "…", "description": "…", "status": { "label": "…", "severity": "success" }, "actions": ["<操作 id>"] }] }
markdown无{ "text": "## Markdown" }
empty无{ "title": "…", "text": "…" }：“暂无内容”状态
loading无{ "text": "…" }：加载指示

一个模型列表，每行带有状态和它提供的按钮：

  • info 只保留含 label 的行，list 只保留含 title 的行。table 接受对象行，按声明的列取值，缺列留空。每块最多保留前 500 行，日志保留最后 500 行。单元格中的 null 显示为空白，其他非文本值显示为 JSON，每格最多 2048 个字符。Markdown 最多 65536 个字符。进度值会限制到 0–1，非数字显示为不确定进度。未知的 severity 按 info 显示。
  • 列表的行提供其 actions 列出的操作；不写时提供块的全部操作；没有 id 的行不提供操作。点击后（若有 confirm 则先确认）调用 ui.panel.action，并以 row 传入该行的 id。
  • progress、status、markdown、empty、loading 块在回答不是对象时（null，或状态中的路径不存在）不显示，因此后端可以用数据来显示或隐藏它们：扫描时显示 loading 块，没有内容时显示 empty 块。
  • Markdown 渲染时不保留其中的 HTML：文字中的标签按原样显示为文字，链接（http、https、mailto）在浏览器中打开，代码块带有复制按钮。
  • 应用当前版本不认识的块类型会在原处说明无法显示，面板的其余部分照常工作；面板需要较新的块类型时，请提高 engines。
  • 点击操作按钮时，应用先用该操作的表单检查输入，再调用 ui.panel.action，参数为 panel、action、values、context 和 row。普通按钮的 row 为 null，列表按钮的 values 为 {}。后端可以返回 { "notice": "…" } 显示给用户。
  • context 在实例管理中为 { "instanceId": "…" }，在设置中为 { "instanceId": null }。management.sections 中的面板只为扩展自己类型的实例显示和回答。
  • 面板打开、用户点击刷新，或一次操作结束时，应用并发查询所有使用 ui.panel.query 的块。每次调用的时限为 30 秒。任何一个块查询失败，整个面板都会显示重试入口。操作失败会在面板内显示原因，然后照常刷新查询块。
  • 除 actions 外的块都可以写 "source": "state" 和 "path"：这样的块改为显示后端的界面状态，不再查询（见来自界面状态的块）。跟随的 log 或来自状态的 progress 会随每次推送更新。
  • 面板操作不会停止实例，也不持有实例的维护锁，因此不能修改实例的文件。需要修改时，应为实例类型声明一个自定义操作（见由后端提供的类型）。

界面状态

在 initialize 的 hooks 中列出 ui 钩子的后端拥有一份界面状态：一个 JSON 值，由它的面板和视图显示，状态变化时由后端主动推送，无需轮询。不列出 ui 的后端不受影响。

方向方法参数结果
应用 → 后端ui.statecontext状态
应用 → 后端ui.callaction、args、context任意值，只返回给调用方
后端 → 应用ui.emit（通知）state、可选的 instanceId无
  • context 在实例管理中为 { "instanceId": "…" }（仅限扩展自己类型的实例），其他地方为 { "instanceId": null }。推送状态时传入可选的 instanceId，只有该实例的面板和视图会收到状态。省略则广播给所有订阅者。
  • 含状态块的面板会在打开、后端重启以及每次推送后读取 ui.state，因此该方法应尽量轻量。视图页面自行调用 state() 读取初始值，用 onState(listener) 接收后续推送。ready() 只启动页面握手和高度报告。ui.state 和 ui.call 的时限各为 10 秒。
  • 错误保留其类别：INVALID_PARAMS 为 invalid，PERMISSION_DENIED 为 forbidden，其他为 failed。
  • 推送会合并：第一次立即发送，之后 100 毫秒内保留最近一次广播和该广播之后各实例的最新状态。序列化为 JSON 后超过 256 KiB 的状态不会发送。
  • ui.emit 只能作为通知发送：作为请求发送时，应用回答 METHOD_NOT_FOUND。
  • 后端界面就绪之前（例如在 activate 期间）发送的 ui.emit 会被丢弃。后端应将最新快照保留给 ui.state，供稍后打开的面板和视图读取。
  • SDK：Rust 中从 Handler::ui 返回一个 Ui，用 Host::emit_state 推送；Python 中覆盖 ui_state（以及 ui_call），用 host.emit_state 推送（见 SDK）。

来自界面状态的块

面板中的块可以指定数据来源：

  • "source": "state" 表示块来自界面状态；不写（或写默认值 "query"）时块通过 ui.panel.query 查询。其他值会在安装时报错。
  • path 是状态中以点分隔的对象键路径（"greetings"、"queue.jobs"）；不写时块显示整个状态。没有 "source": "state" 却写了 path 会在安装时报错。
  • 路径处的内容按 ui.panel.query 对该块的回答来写（{ "rows": [...] }、{ "lines": [...] }），由应用以同样宽松的方式读取，限制也相同。上例的状态为 { "greetings": { "rows": [{ "to": "world" }] } }。
  • 块会跟随每次推送更新，无需查询：应用会再次读取 ui.state，显示路径处的内容。状态无法读取时，块会在原处说明原因，直到收到新的状态；后端未运行或未列出 ui 时，块不显示任何行。

视图（frame）

清单中 kind = "frame" 的 ui 项是一个视图，entry 是软件包中的 HTML 页面。设置窗口中的视图以它的 title（或扩展名称）为分区名；management.sections 中的视图只在扩展自己类型的实例中显示。

pages 中的视图是应用中单独的页面而不是分区，适合不属于任何实例、又比设置分区大的界面（下载器、模型库等）。这里只能放视图。它的调用和状态与设置中的视图相同：没有实例。

  • 只要有扩展提供页面，标题栏就会显示“扩展页面”按钮；其菜单按 title（没有时为扩展名称）列出每个页面，选择后在 /extensions/<扩展 id>/<视图 id> 打开。
  • 页面占满标题栏下方的内容区域，标题栏显示它的标题。它没有标题头，也没有自己的高度：无论页面报告多高，视图都占满整个区域，因此页面应自行滚动内容。
  • 扩展关闭或失败时，页面会在原处说明原因。

页面如何加载

视图页面通过应用注册的 hfext 协议从扩展当前启用版本的目录中只读加载：

平台页面地址
Linux、macOShfext://<扩展 ID>/<路径>
Windowshttp://hfext.localhost/<扩展 ID>/<路径>

只使用相对 URL

在 Windows 上，软件包根目录是 /<扩展 ID>/ 而不是 /。以 / 开头的绝对路径在 Windows 上会指向错误的位置，页面中的脚本、样式、图片都应使用相对 URL（如 ./status.js、../__hanafubuki/frame.js）。

只有软件包中的普通文件可以加载；..、反斜杠、指向包外的链接、目录或不存在的文件都返回 404，扩展未运行时也返回 404。内容类型由文件扩展名决定（html、js/mjs、css、json、svg、png、jpg、gif、webp、avif、ico、woff/woff2、ttf、otf 等）。

视图客户端

应用在每个软件包根目录的保留路径 __hanafubuki/frame.js 提供视图客户端（软件包中同名的文件会被它取代）。它是一个 ES 模块，用相对 URL 导入：

函数说明
ready()通知应用页面已就绪。之后应用发送主题、跟随页面高度并定期 ping。10 秒内不调用，视图会显示“不可用”
call(method, params)调用后端，后端收到 ui.frame.call，参数为 frame、method、params 和 context（实例管理中为 {instanceId}，设置和单独页面中 instanceId 为 null）；返回的 Promise 以后端的回答完成，失败时以 FrameError 拒绝
on(event, listener)监听后端通过 ui.frame.emit 发给这个视图的事件，返回取消监听的函数
state()读取界面状态（带视图上下文的 ui.state）；以状态完成，失败时以 FrameError 拒绝（没有 ui 钩子时为 unavailable）
onState(listener)监听后端推送的每个状态（ui.emit），返回取消监听的函数。开始监听前推送的状态不会补发，因此也要调用一次 state()
getSettings()、patchSettings(patch)通过宿主读写扩展自己的设置，纯数据扩展也可使用。设置示例
openSettings(section)、openExternal(url)打开已注册的设置分区或 HTTP(S) 链接。导航示例
pickDirectory({ title }?)打开应用的文件夹对话框（title 超过 200 个字符会被截断），以用户选择的本机路径完成，取消时为 null。页面只得到路径，无法读取该文件夹：把它交给后端处理
updateInstance(values, mode?)仅在管理视图内使用。提交安装参数（最多 64 项），确认后执行 "update" 或原地 "reinstall"。省略时，就绪且提供更新的类型执行更新，其余执行原地重装。原地重装时用户可在宿主确认框中勾选要删除并重建的组件，默认均不勾选。更新保留全部组件目录。
navigateInstance(instanceId)打开某个实例的页面，例如下载器在注册实例之后；应用开始前往时完成，视图可能随之关闭
locale()应用的语言（en、zh）；ready() 之后第一次收到主题之前为 null。客户端也会把它设为根元素的 lang
onLocale(listener)监听应用的语言：第一次收到时以及每次变化时调用，返回取消监听的函数

客户端的类型声明是 sdk/frame/frame.d.ts，与组件包的类型声明一起放在下面的「视图类型声明」压缩包中。页面用相对 URL 导入运行时的 __hanafubuki/frame.js，而 paths 不解析这类相对导入：请在自己的仓库中为这两个 URL 各写一条声明，再把声明导出的名字映射到压缩包里的文件。不要自己另写一份类型。

视图类型声明

视图页面所导入内容的类型声明：__hanafubuki/frame.js 的客户端与 __hanafubuki/ui.js 的组件包，并附引用它们的 tsconfig 映射。downloads/extension-frame-sdk.zip· 34.4 KB· 压缩包内容 frame-sdk

压缩包中的 README 给出了声明文件和 tsconfig.json 的完整写法，组件包的类型声明需要从 vue 解析 Vue 的类型，也要在那里指向应用所用的 Vue 版本。

FrameError 的 kind 为：

kind含义
unavailable没有后端（纯数据扩展），或后端未运行
timeout后端未在 30 秒内回答（state() 为 10 秒）
invalid调用本身无效，例如实例不属于该扩展的类型，或在实例管理之外调用 updateInstance
forbidden仅 state()：后端拒绝（PERMISSION_DENIED）
failed后端返回了错误；对 updateInstance 而言，是用户拒绝、已有更新在等待回答，或应用拒绝（附原因）

后端发送通知 ui.frame.emit（参数 frame、event、payload）时，该扩展所有打开的、ID 为 frame 的视图中订阅了 event 的监听器都会收到 payload；其他扩展的视图收不到。它只能作为通知发送：作为请求发送时，应用回答 METHOD_NOT_FOUND。传入可选的 instanceId 时，只有该实例的视图会收到事件。Rust 使用 emit_frame_for(Some(id), frame, event, payload)，Python 在 emit_frame 中传入 instance_id=id。

客户端还会：

  • 用 ResizeObserver 报告根元素（<html>）的高度，视图高度跟随它，限制在 96 到 4096 像素之间（就绪前为 240）；页面不应把根元素高度设为视图高度（pages 中的页面忽略它，占满整个区域）。
  • 在页面中按 Escape（且页面没有阻止该事件）时把焦点移出视图。
  • 自动回答应用的 ping；12 秒没有回答的视图显示“不可用”，“重新加载”会重建它。

界面套件

组件包

应用还会把自己的 Vue 组件提供给每个视图。它们与应用由同一份源码构建，因此总是与所运行的应用版本一致：

  • __hanafubuki/vue.js：Vue 运行时。它不含模板编译器，视图的安全策略也不允许 eval，因此请用 h() 渲染，或提供由你自己的构建编译好的模板。
  • __hanafubuki/ui.js：组件。它只导入 ./vue.js，因此你的页面也从 ../__hanafubuki/vue.js 导入 Vue，页面中就只有一个 Vue。
  • __hanafubuki/ui-components.css：组件自己的样式，在 ui.css 之后引入。

在每个 Vue 应用上安装 frameUi(frame)，参数是视图客户端模块：它让组件使用应用的语言（并跟随切换），浏览按钮使用应用的文件夹对话框。useUiStrings().t(key) 让你的页面使用同样的文字。frameUi(frame, { teleportTo, openLink }) 接受两个选项：菜单和提示框放置的位置（默认是 body），以及点击 MarkdownDocument 中的链接时如何处理它的地址。

组件及其属性、事件和插槽列在接口参考中；类型声明是 sdk/ui/ui.d.ts，在视图类型声明压缩包里。它由组件包的源码生成，覆盖每个组件的属性、事件和插槽，以及 frameUi 和动效工具。这些组件属于 UI API 1（UI_API_VERSION）：之后的版本可能新增组件和可选属性，删除或重命名则是新版本。请把 engines.hanafubuki 提高到新增了你所用内容的应用版本。

组件在视图中的行为与在应用中相同，只是限于视图之内。PathInput 只能选择文件夹（kind: "file" 的字段不会打开对话框）。菜单在以下情况关闭：在菜单外按下（页面中或应用中）、Escape、Tab、触发器所在区域滚动，以及视图大小改变。在设置分区中，视图跟随页面高度，因此菜单可能打开时请保持页面高度不变（不断增长的日志应放在固定高度的容器中）。视图中任何滚动都会隐藏提示框，并关闭标签页的溢出菜单。

组件包包含应用中所有能在视图里运行的共享组件：

安全限制

视图是不受信任的内容，运行在 sandbox="allow-scripts" 的 iframe 中（没有 allow-same-origin），源为不透明的 null。每个响应都带有以下内容安全策略：

其中 <自身> 是扩展自己的地址（hfext://<扩展 ID>，Windows 上为 http://hfext.localhost/<扩展 ID>/）。因此视图：

  • 没有网络：connect-src 'none' 禁止 fetch、XHR 和 WebSocket；需要的数据通过 call 交给后端获取。
  • 没有内联脚本：脚本必须是软件包中的文件；内联样式可以使用。
  • 只能加载自己软件包中的资源：图片另外允许 data: 和 blob:。
  • 没有弹窗和对话框：沙箱不允许打开新窗口，也不允许 alert、confirm、prompt；不允许提交表单。文件夹对话框由应用通过 pickDirectory 打开。
  • 没有应用接口：视图中没有 Tauri 的脚本或调用密钥，无法调用应用的任何命令；它只能通过视图客户端与宿主组件通信。

一个视图出错、未就绪、停止响应或调用挂起，只影响它自己，其他视图和面板照常工作。但在 WebKitGTK 和 WKWebView 中视图与窗口运行在同一进程中，长时间阻塞主线程的页面会让整个窗口卡住。

打开宿主设置和外部链接

openSettings 接受当前已注册的设置分区 ID。内置分区可用 network 等 ID，扩展设置表单用 extension:<扩展 ID>，位于 settings.sections 的面板或视图用 extension:<扩展 ID>:<面板或视图 ID>。示例打开 Greeter 的问候面板，需要先启用 Greeter。未知分区会得到 invalid。openExternal 通过系统浏览器打开 HTTP(S) 地址，打开失败会返回原因。两个调用都可以在纯数据扩展中使用，成功时返回的 Promise 以 undefined 完成，失败时以 FrameError 拒绝。

主题变量与局部动效

完整变量字典 保留选择器、浅色覆盖、派生表达式、减少动态效果条件及 runtime writer。共享样式提供基础声明，匹配的浅色选择器和局部规则覆盖它们，宿主主题消息再将投影值写入 inline style。应查看每项实际条件，不把所有变量当作可互换的全局默认值。公开组件的局部变量只影响文档指定组件，实现变量不是扩展设置。

从 __hanafubuki/ui.js 使用 frame 安全动效工具，并从 __hanafubuki/vue.js 使用宿主 Vue。通过 CSS role 读取 timing，让工具遵循减少动态效果偏好，在 Vue scope 结束时释放动画、固定尺寸和观察器。useDeferredPresence 只保留离场期间的内容，不自行播放动画；拥有过渡的组件在离场结束时调用 closed。可运行示例 在现有 linked gallery 演示尺寸／方向切换、FLIP／指示器和延迟卸载展开。不需要后端或额外权限，也不获得原生窗口或应用全局主题控制权。

字典记录源码声明及条件，最终值只能由运行中的浏览器结合继承和 inline 覆盖计算；gallery 的主题查看器读取的正是该实时值。若将 motion 耗时写入 inline style，它可能覆盖样式表中的减少动态效果声明。自定义脚本动画必须检查 prefersReducedMotion()，或使用已有此检查的共享工具；一个 timing 数值本身不代表用户偏好。不要仅为定制一次过渡而覆盖共享 timing role。
