实例类型

用描述文件声明实例类型：组件、运行时、安装参数、安装与更新步骤、占位符、服务器角色、管理操作、发现，以及由后端提供的类型。

扩展通过描述文件为应用添加实例类型。清单中 contributes.instanceTypes 的 glob 匹配的每个 .toml 或 .json 文件都是一个类型，其 ID 为 <扩展 ID>:<name>，例如 com.example.llama:llama-server。用户新建安装时可以选择这些类型，应用根据描述完成安装、启动和管理。

描述文件按宽松方式解码，未知字段会被忽略；但未知的步骤类型、就绪检查或运行时会被拒绝。所有检查在注册时进行，任何问题都会带着位置（如 servers[1].command[0]，或行列号）报告，类型不会被注册，扩展也无法安装。

组件

组件可用 defaultPath = "assets/weights" 指定安装根下的相对默认目录，显式选择的路径优先。类型可设置 [terminal].cwd 为 "{component.core}/tools" 等组件路径，让实例终端直接在 CLI 的目录中打开。省略时终端在 core 目录打开。

组件是实例的目录。默认情况下，每个组件位于安装目录下的同名子目录 <安装目录>/<name>，用户新建时也可以把组件放到别处。步骤和命令通过 {component.<name>} 引用组件，从不直接写路径。core 总是存在，服务器进程以它为工作目录。

新建实例默认拥有各组件。在“路径”中选择外部目录时，宿主会检查该目录是否存在。如果声明了当前平台的 executable，还会检查该目录下是否有对应文件。发现也可以在导入时标记外部组件。受管的 python 组件始终归实例所有。

删除或重装实例时，宿主会保留外部目录。目标位于外部目录中时，git-clone、unpack 和指定 unpackTo 的 download 会被拒绝。下载到单个文件、write-file 和 git-pull 仍可修改其中的内容。后端规划 run 步骤时，应先读取组件的 external 标志，再决定是否让自己的程序修改文件。

组件可声明 rebuildable。例如下面的声明在维护页提供「强制重建 Node.js」，并隐藏 Core 的重建开关。省略时，core 和 python 提供开关，其他组件默认隐藏。开关默认关闭，只对本次安装生效；外部目录不能重建。

文本

displayName、description、组件的 label 以及参数的 label、help、disabledReason 和选项标签可以写成：

  • 纯文本："llama.cpp server"，所有语言相同；
  • 按语言：{ en = "…", zh = "…" }；
  • 文字键：{ key = "ext.<扩展 ID>.<键>" }，从扩展的文字文件读取（见界面）。键必须以本扩展的 ext.<扩展 ID>. 开头，引用应用或其他扩展的键会报错。

安装参数

[[install.parameters]] 中的每一项都是安装表单中的一个字段，新建安装时显示在一个分组中。实例的参数值称为它的 spec。

键说明
name必填，由 A-Z、a-z、0-9、_、- 组成，不能重复；占位符用 {param.<name>} 引用它
kind必填：text、number、boolean、select、multiselect、path、secret、slider、textarea
label标签；省略时显示 name
help帮助文字
required是否必填，默认 false
default默认值，必须是该字段能接受的值
optionsselect 和 multiselect 的选项（必填）：值的列表，或 { value = "…", label = … } 的列表；值不能重复
min、max、step数字范围与步长；min 不大于 max，step 为正数；slider 必须同时有 min 和 max
pathpath 字段选择的是 directory（默认）还是 file
advanced有可用的默认值，新建表单会把它折叠起来
visibleWhen条件成立时才显示；不显示的字段不会保存值
requiredWhen条件成立时必填
disabledWhen条件成立时禁用，配合 disabledReason 说明原因

条件写作 { key = "<字段>", equals = <值> }，或用 { any = [...] }、{ all = [...] } 组合多个条件，只能引用已声明的字段。

参数值只在进入应用时读取一次：

  • 请求中出现未声明的字段会被拒绝；已保存的 spec 中多出的字段会被丢弃；
  • 每个值必须符合字段类型：数字在范围内且符合步长，select 是某个选项，multiselect 是选项列表；
  • null、空文本和空列表视为没有值，使用默认值；
  • visibleWhen 不成立的字段会丢失其值；必填（或 requiredWhen 成立）且显示的字段没有值时会被拒绝。

secret 以文本保存

secret 字段只是在界面上隐藏输入内容，它的值与其他参数一起以文本形式保存在实例的记录中。

占位符

字符串中的占位符在执行时按文本替换，没有表达式语言：

占位符值可用位置
{component.<name>}已声明组件的目录步骤、服务器命令与环境变量
{param.<name>}已声明参数的值；列表用逗号连接，未设置时为空步骤、服务器命令与环境变量
{instance.id}实例 ID步骤、服务器命令与环境变量
{instance.root}实例的安装目录步骤、服务器命令与环境变量
{port}服务器分配到的端口仅服务器的 command 和 env
{endpoint.<role>}当前角色 after 中声明的同实例角色就绪后的服务地址仅服务的 command 和 env
{extension.root}扩展的包目录（开发链接时为其文件夹）步骤、服务器命令与环境变量
{host.python}应用托管的 Python，即 Python 后端所用的解释器步骤、服务器命令与环境变量

写 {{ 和 }} 表示字面的花括号。引用未声明的组件或参数、在别处使用 {port}、未闭合的 { 都会在注册时报错。

{extension.root} 用来定位包内文件，步骤的输出写到组件路径。run 步骤或服务器的程序是 {host.python} 时，它可以导入应用的 sd_webui_all_in_one（启动器代码位于 PYTHONPATH 最前），并设置 PYTHONUTF8、PYTHONUNBUFFERED、PYTHONNOUSERSITE 为 1。应用运行时正在准备解释器时，解析该占位符会等待；如果准备已失败，操作会返回运行时的错误。

步骤的路径字段（to、unpackTo、archive、into、dir、cwd、path）以 {component.<name>} 开头，之后可以用 / 接组件内的路径，例如 {component.core}/bin/server。如果解析后的路径会离开组件，该步骤会被拒绝。environment.path 的条目还可以从 {instance.root} 开始。

步骤

首次安装和重试执行 [[install.steps]]。显式重装可以用 [[reinstall.steps]] 指定另外一组步骤，省略时沿用安装计划。步骤可以带本地化标题，例如 title = { zh = "生成模型索引", en = "Build model index" }。工作区会显示当前步骤标题，失败后也能查看。对于静态类型，[[update.steps]] 是已就绪实例更新时执行的步骤（没有声明时使用 install.steps）。步骤按顺序执行，第一个失败的步骤使整个操作失败。安装进度会显示当前步骤和已完成的数量。

kind键说明
downloadurl、sha256，以及 to 或 unpackTo 之一经应用代理下载，https://github.com/... 会先尝试配置的 GitHub 镜像。sha256 必填：64 位十六进制，或引用一个参数；摘要不符时不替换任何内容。to 保存为文件，unpackTo 解压到目录，可同 unpack 一样指定 strip
unpackarchive、into，可选 strip解压 zip 或 tar（gz、xz、bz2）；会离开目标目录的条目或链接会被拒绝；已有目录时逐项替换同名条目并保留其他内容。strip = N 去掉每个条目路径的前 N 段（1 即去掉压缩包的顶层目录）；去掉后不剩内容的文件、或去掉后同名的两个条目会被拒绝。tar 中的符号链接可以用开头的 .. 指向上层（如 Node.js 的 bin/npm -> ../lib/...），但不能指出 strip 保留的部分
git-cloneurl、into，可选 branch使用应用的 Git 克隆；目标处已有仓库时跳过，交给 git-pull
git-pulldir拉取已有仓库
runcommand，可选 cwd（默认 {component.core}）和 env直接执行程序（不经过 shell），command 第一项是程序；输出记入任务，失败时附带最后 4 KiB 输出
python-env无在 python 组件中准备应用管理的 Python；之后的 run 步骤会优先在 PATH 中找到它。仅用于 Python 运行时
write-filepath、content写入文件；目标目录解析到组件之外时被拒绝
probeurl，可选 timeoutSeconds（默认 60）等待本机 http:// 地址（127.0.0.1、localhost 或 [::1]）返回 2xx

unpack 和指定 unpackTo 的 download 还支持 replace = true。当更新需要清除旧版本独有的文件时，可以使用该选项。宿主先在目标目录旁完成解包，再整体替换目标目录。如果其中包含实例的其他组件，宿主会拒绝替换。省略 replace 时，解包到已有目录会保留与本次解包无关的条目。

服务器

每个 [[servers]] 是一个服务器角色。声明式类型的启动就是按顺序启动它的所有服务器。

键说明
role必填：1 到 64 个 a-z、0-9、- 字符；control 是管理 API（见下文）
command程序及参数，第一项是程序。后端类型可省略此项，由 provider.launchPlan 规划该角色
env环境变量，值可以使用占位符
port{ allocate = true }（默认，自动分配）、{ fixed = 8080 }、{ param = "<数值安装字段>" } 或 { launch = "<数值启动字段>" }
readiness除 control 外必填。从 { http = "/health" }（绝对路径）、{ tcp = true }、{ stdout = "<正则表达式>" }、{ captured = true } 中选一种。可选的 timeoutSeconds 默认为 120。
after在哪些角色之后启动；不能引用未声明的角色，不能形成循环
restartnever（默认）或 on-failure（失败后在限额内自动重启）
webview为 true 时，该角色运行后其地址会作为页面出现在 WebUI 标签页中；默认 false
required默认 true。必需角色失败会使启动失败；非必需角色失败时实例以降级状态继续运行

服务器进程以 core 组件为工作目录。env 中的变量与实例的环境变量合并，同名时以实例的为准。

界面位于子路径时，可以设置 webview = true、webviewPath = "/dashboard/"，健康检查仍可使用独立路径。用 externalBrowserPath = "/studio" 可以为顶部栏的浏览器按钮单独指定同源页面。 声明 after = ["api"] 的角色可在命令和环境中使用 {endpoint.api}。宿主在启动时填入本实例已就绪的 API 服务地址，含实际分配的端口。

如果服务自行决定浏览器打开的地址，例如 URL 中带有会话令牌，可以用 readiness = { captured = true }。宿主每次启动时分配新的运行时代理会话，程序通过 browser.open 事件上报本机回环 HTTP(S) 地址。使用 sd_webui_all_in_one 时，可用 DesktopBrokerClient.from_env() 创建客户端，再调用它的 emit_event("browser.open", {"url": url})。宿主收到第一个有效地址后将角色标为就绪；配置 webview = true 时，页面会保留 URL 中的查询参数。只向标准输出打印地址会让这种探测一直等到超时。

管理 API

使用 Python 运行时的类型还可以在实例自己的 Python 上运行应用的管理 API，即每个内置 WebUI 都运行的控制服务器。声明 control 角色（只能写 after 和 required），并让自己的角色在它之后启动：

应用会先启动它，再启动你的角色；实例信息和“设置 → API 服务器”中会显示该实例的管理 API，实例被管理或启动期间它保持运行。停止或重启它不会停止你的角色。没有 Python 运行时的类型不能声明 control，错误信息会说明原因。仅声明这个角色不会增加任何管理页；类型通过采用内置类型的管理功能获得内置 WebUI 的版本、扩展、模型和 PyTorch 管理页。

用 [[launch.parameters]] 声明每个实例的启动字段，写法与安装参数相同。用户在「启动」页修改，下次启动服务时生效，无需重装。服务命令和环境变量可引用 {launch.name}。服务可用 cwd = "{component.core}/service" 指定工作目录，默认使用 core。后端启动计划同时收到安装参数 values 和启动参数 launchValues。

在 [launch] 设置 preflight = true 后，宿主在启动整组服务前调用一次 provider.launchPreflight，传入 type、instance、安装参数 values 和已应用默认值的 launchValues。只读检查成功时返回 {}，失败时返回带原因的 RPC 错误。例如，greeter 在启动前检查所选问候语文件是否仍然存在。单独重启服务角色时不会重复检查。

扩展有后端时，kind = "select" 的启动字段可以声明 optionsSource = "models"。用户打开某个实例的「启动」页时，宿主调用 provider.launchOptions。例如，返回 { "options": { "models": ["a.gguf", "b.gguf"] } } 即可列出这个实例的模型。管理工具 get_instance_launch_options 按字段名列出该实例可选的非秘密候选。静态选项仍然可选。保存新选中的动态值时，宿主会核对该值。后端离线或旧模型已经移除时，可以保留已保存的值。

类型顶层可写 quickPaths = [{ name = "输出", component = "core", path = "output" }]，在创建、导入或扫描纳管时生成概览中的初始快捷目录。之后由用户重命名、排序或删除。迁移时指向原实例根目录内的快捷路径同步移动，其他快捷路径保持原目标。可以在类型顶层声明本地化 migrationNotice，在迁移预览中提示用户软件配置中可能需要更新的绝对路径。

环境

[environment] 作用于类型的 run 步骤、服务器和终端：

unset 按完整名称或带末尾 * 的前缀移除继承的变量。Windows 匹配变量名时忽略大小写。显式设置的同名变量仍会生效，实例自己的环境变量优先于 vars 以及步骤或服务器的 env。path 的每一项都从组件或实例根目录开始。{port} 仅用于服务器角色的命令或环境变量。

管理操作

[management] operations 列出实例提供的标准操作之外的管理操作。声明式类型可以声明 update 和 terminal。声明 update 后，已就绪实例的“更新”会执行 update.steps（或 install.steps）；不声明则不能更新。声明 terminal 后，实例提供以 core 为目录、带有类型环境的终端。

只读模型组件

在 components 中声明组件（例如 weights），再在 [management] 下设置 modelComponent = "weights"。用户即可在「模型」页浏览此实例该组件的文件和文件夹，包括位于实例目录之外的组件。MCP 也可通过 list_model_entries 和 list_model_directories 浏览。此功能无需控制服务器，且只允许读取。只读模型组件与从内置类型采用的 models 操作只能选用其中一个。

采用内置类型的管理功能

类型可以采用一个内置类型，按需选择应用提供的管理功能：

在 [management] 中使用 allowedMutations = [] 可提供只读分区，也可列出允许的写操作，如 ["model.download", "extension.update"]。模型库安装和 PyTorch 重装分别使用 model.library_install 和 pytorch.reinstall。省略此项时沿用该类型原有的操作范围。

adopts 用类型 id 指定一个内置类型：builtin:sd-webui、builtin:comfyui、builtin:invokeai、builtin:fooocus、builtin:sd-trainer、builtin:qwen-tts-webui、builtin:rvc-next-webui 或 builtin:mizuoto-tts-webui。类型需要满足：

  • runtime = { kind = "python" } 并声明 control 角色：这些管理页由管理 API 提供；
  • core 是实例自己的目录。core 声明了 external = "allowed" 的类型不能采用，因为这些管理页会修改 core 中的内容。

models模型：core/models（SD Trainer 为 core/sd-models）下的文件，以及被采用类型的模型库core 的目录结构与被采用类型的安装一致
environment管理工具读取的环境报告实例的 python 是程序运行的环境
pytorchPyTorch 目录与重装实例的 python 是程序运行的环境

类型可以只为 versions 和 environment 采用，这两项不要求特定的目录结构。被采用的类型是否支持某个管理页由该类型决定：采用 builtin:fooocus 没有扩展管理，对应的管理页会显示为不支持。采用 builtin:invokeai 只有扩展管理和环境报告：它的版本、模型和 PyTorch 重装属于它自己的软件包。

以下功能仍是内置类型专有的，对你的类型会被拒绝：

  • 内核更新及其更新摘要。 类型自己的 update 就是它的更新，update-check 就是它的检查。发现的更新显示在“维护”中“更新”操作旁边。
  • 快照，包括从快照创建实例。
  • 热补丁、启动参数和启动检查。 你的服务器由你自己的命令启动。
  • 分支变体。

编写类型时需要知道两点：

  • 切换到某个提交后，core 处于分离状态。如果 update.steps 是 git-pull，它会报告这一点；请为这种情况编写你想要的步骤。
  • 实例启动期间不能重装 PyTorch。从“设置 → API 服务器”启动的角色不算启动，因此重装 PyTorch 前请先停止这样的角色。

示例 adopted-webui 是一个完整的此类类型。

发现

应用的发现功能（扫描实例，以及把文件夹拖到应用上）按目录结构识别内置 WebUI。你的类型用 [[discovery]] 特征识别它自己的已有安装；没有特征的类型不会被发现。

  • 扫描访问每个目录时，先尝试内置结构；再在已发现的安装之外，按顺序尝试已注册类型的特征。被特征匹配的目录不再继续向下扫描。
  • 标记必须是普通文件或目录，且途中不经过链接。路径为相对路径，以 / 分隔，只包含普通名称：..、开头的 /、反斜杠或盘符在注册时被拒绝。
  • components 只能写类型声明的组件。其他组件为 <根目录>/<name>，且每个组件都必须存在：导入只接纳已有的目录。
  • values 在注册时按安装参数检查：未知参数，或既无值也无默认值的必填参数，都会在 discovery[<序号>].values 处报告问题。其余参数取默认值。
  • 匹配到的目录作为你的类型的就绪实例导入。已被管理的目录只会被报告，不会重复导入。若类型此时拒绝这些值（由后端提供的类型会调用 provider.validateSpec），或某个组件在磁盘上不存在，它会成为一条警告而不是实例。
  • external = ["core", "node"] 把接入的安装的这些组件记录为外部组件（每个都须声明 external = "allowed"）：删除或重装实例都不会删除它们。
  • 顶层的 attachOnly = true 让发现成为得到实例的唯一途径，适用于用户自己装好的安装，例如 npm 全局前缀：创建页面不列出该类型，手动创建或导入会被拒绝。设置它的类型必须声明特征。
  • 特征随类型一起离开：扩展关闭后，它的类型不再被发现。

由后端提供的类型

写 provider = "backend" 的类型保留描述中的静态部分（ID、文本、组件、运行时、参数、服务器、操作），把动态部分交给扩展的后端：

  • 扩展必须有 [backend]，否则安装时报错。
  • 可用 install.steps 声明安装步骤（包括空列表），用 [reinstall] 覆盖显式重装步骤，用 [update] 声明更新步骤。省略的阶段由后端规划。每个服务角色可以声明静态 command，也可以省略并调用后端获取命令。
  • operations 除 update 和 terminal 外还可以有 update-check 和自己的操作，名称由 a-z、0-9、- 组成，不能是内置类型的标准操作名（launch-arguments、snapshots、hotpatch、diagnostics；versions、extensions、models、environment、pytorch 只能通过采用内置类型的管理功能声明）。
  • update-check 让实例参与应用的更新检查：卡片上的“检查更新”和每日检查会调用后端的 provider.checkUpdate（实例运行时也会调用），发现的更新显示在卡片上，以及实例管理的“维护”页。它不是自己的操作：实例管理中不会为它列出按钮。有后端的扩展可以单独声明这项能力，同时可以保留静态安装步骤和服务命令。

自定义维护操作可以在操作页收集参数、显示确认文案。表单复用安装参数的写法。后端收到宿主校验后的 values，管理工具 run_instance_operation 也接受相同的参数对象。 管理面板的列表动作可指定 operation = "refresh-index" 和 rowField = "target"，由宿主把所选行 ID 填入操作的文本字段。 耗时操作可以返回 steps。宿主持有独占维护权并执行步骤，调用者通过活动 ID 在任务中心跟踪和取消。

后端通过以下回调参与（详见后端）：

时机回调后端返回
检查参数值provider.validateSpec按参数列出的问题；应用先完成自己的表单检查再询问后端
安装、重试、重装、更新provider.installPlan步骤列表，写法与 install.steps 相同，包括占位符
启动一个角色provider.launchPlanargv 和 env，写法与服务器的 command、env 相同，可以使用 {port}

执行自己的操作provider.manage.<operation>可选的提示文字及维护步骤计划

应用会像检查描述中的步骤一样检查后端返回的计划：引用未声明的占位符、路径不以已声明的组件开头、未知的步骤类型，或值会离开组件，都会使整个计划在执行前被拒绝。后端只命名组件，从不给出路径；步骤由应用执行。

读取已有实例记录从不询问后端，因此后端停止时实例仍能列出。后端出错或重启期间，这些类型保持注册，但需要后端的操作会失败并提示扩展后端不可用；扩展关闭、更新或卸载时类型才会移除。

预设

预设是某个实例类型的一组默认值，全新安装页面会把它列在该类型下：选择后会填写表单，用户仍可修改每个值。清单中 contributes.presets 的 glob 匹配到的每个 .toml 或 .json 文件都是一个预设，其 ID 为 <扩展 ID>:<id>，如 com.example.greeter:morning。其基础类型可以是本扩展的类型、其他扩展的类型或内置类型。
